# Phone normalisation fix — honour the written country code, and stop caching OTP responses

The change adds a strict normaliser beside the defective one rather than repairing it, and wires it at four customer-facing phone doors. `normalize_phone_preserving_country` reads the `+` / `00` marker on the trimmed original text and only then strips to digits, which is the ordering that makes the fix possible at all; `normalize_phone` is byte-identical (`+120 / -0` on `customer.py`, zero deleted lines across all four task commits). The second, independently written copy of the same defect in the standalone `customer-whatsapp-auth` Cognito trigger is fixed in place and pinned to the canonical implementation by a drift-agreement test over one shared case table. Finding 2 adds a `no-store` contract to `customer_session.py` and applies it at every return path of the two auth handlers we own without touching `response.py`. Finding 3 is reported with `simulate-principal-policy` evidence and a proposed explicit `Deny`, not applied.

Every substantive correctness check in the review brief passes, and I verified the anti-delegation guard by mutation rather than by reading it. The blocking problem is elsewhere: the change is **deployed**, on two live `live` aliases and one unaliased function, and its own evidence document asserts the opposite.

Watch for: the doc's "No deploy was performed. No `update-function-code`, no version publish, no alias move" is contradicted by direct measurement — `wecare-customer-whatsapp-auth` `live` now points at version 11 carrying this change's `_normalise_phone` (**confirmed**, exact CodeSha256 match against a locally reproduced package, pre-fix sha does not match); `wecare-customer-session` `live` points at version 4 whose package contains `harden_session_headers` (**confirmed**, read out of the live zip); `wecare-seo-tools` `$LATEST` was redeployed by CI because the push that carried these commits matched `seo-tools-deploy.yml`'s `lambda_utils/**` path trigger (**confirmed**, CloudTrail). No rollback version was recorded before the alias moved (**confirmed**, absent from the doc).

**Verdict**: NEEDS_CHANGES

## High-level view

The normaliser design is right and the ordering argument is carried through the implementation, not just the docstring. The marker branch runs on `compact`, produced by a separator class (`[\s\-().]`) that matches neither `+` nor a digit, and the `re.sub(r"\D", "", ...)` happens strictly after. `MissingCountryCode` subclassing `InvalidPhoneNumber` → `ValueError` is what lets both registration call sites keep their existing `except` clauses unchanged, so no handler control flow moved.

The three guards against a future refactor to delegation are real, not decorative. I built an in-memory mutant of `customer.py` in which the strict function is replaced by the classic "call `normalize_phone`, then inspect the result" wrapper, and all three guards reject it: the monkeypatch tripwire fires on both the `+` and the `00` input, the AST delegation guard sees the call, and the ordering guard fails because the delegating body has no post-branch digit strip.

Only the four planned entry points are wired. The union of files across the four task commits is eleven, and `build_customer`, `validation.py::normalize_phone`, the five messaging callers, `outbound-whatsapp`, `sinch_rcs`, `checkout`, `customer_cart`, `initiation`, `address.py`, `crm`, `response.py` and everything under `src/` are all absent from it.

The trigger fix stayed in place, and the handler still imports nothing from `lambda_utils` — asserted by an AST test, which matters because the function is packaged `standalone=True` with no layers. The two implementations are held together by a drift test parametrized over the same seventeen-row table the canonical function is tested against.

The `test_registration.py` migration changed constants and added a replacement test. The one-counter parametrize lost its two bare spellings and kept its three explicit-code ones; the bare pair moved to a new sibling asserting `INVALID_PHONE`, HTTP 400, nothing sent and no counter consumed. No assertion was weakened, and `test_the_verified_body_carries_no_phone_number` is untouched.

The no-store work is applied per return path at the handler, with `response.py` left alone and a test pinning that absence so a future session cannot "tidy" the header into the shared builder and silently override `core/contacts/handler.py:285`. The AST guard over `return <builder>(...)` is the right shape for a finding that is about *every* path, and it carries a non-vacuity assertion plus a positive control on the `csrfToken` detector.

Finding 3 is reported and not applied. CloudTrail confirms it: the only IAM policy writes in the account on 2026-10-01 are `CustomerSessionCustody` on the session role and `CheckoutLeastPrivilege` on the checkout role, both other workstreams. Nothing touched `wecare-digital-lambda-role`.

What is wrong is the deployment record. Three production mutations carry this change, and the doc states that none happened. The doc is the project's evidence artifact; a false production claim in `docs/execution/` is worse than no claim, because the next session reads it as measured state.

## The pre-strip branch, verified by mutation rather than by reading

The review brief's first question is whether the marker branch precedes any digit-stripping, and whether a wrapper has been smuggled in. It has not. The relevant body:

```python
compact = _PHONE_SEPARATOR_RE.sub("", text)        # [\s\-().] — matches neither + nor a digit

if compact.startswith("+"):
    rest = compact[1:]
elif compact.startswith("00"):
    rest = compact[2:]
else:
    raise MissingCountryCode(...)

if rest.startswith("0"):
    raise InvalidPhoneNumber("a country code does not start with zero")

digits = re.sub(r"\D", "", rest)                   # strictly after the branch
```

`DEFAULT_COUNTRY_CODE` and `_INDIAN_MOBILE_RE` are never reached. The trunk-zero strip is gated on `digits.startswith("91")`.

Reading the three guards is not the same as knowing they fire, so I built an in-memory mutant: `customer.py` with `normalize_phone_preserving_country` replaced by a delegating wrapper that calls `normalize_phone` and then raises `MissingCountryCode` if the raw text lacks a `+`. Nothing on disk was touched. Result:

```
guard-1 tripwire   : FIRES on both inputs
guard-2 AST deleg. : FIRES
guard-3 ordering   : FIRES (no post-branch \D strip in the mutant)
```

Both inputs the brief asks about are covered — `'+6591234567'` and `'0065 9123 4567'` — the two branches a careless wrapper collapses. The statement-ordering guard catches what the delegation guard cannot: a body that avoids all three forbidden symbols and still strips digits first. It was added beyond the plan, with the reason recorded.

One gap worth naming, since it is the only way past all three: a module-level alias (`_legacy = normalize_phone`) called from the strict body would evade both the monkeypatch and the substring check on `called`. The ordering guard still catches it, because a delegating body has no `\D` strip of its own. Defence in depth holds, but the delegation guard alone does not.
