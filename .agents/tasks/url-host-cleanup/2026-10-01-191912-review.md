Two obsolete public destinations into the staff tree are gone (the `ErrorBoundary` escape button and the three PWA launcher shortcuts), the `www` → apex 301 that the owner's redirect removal deleted as collateral is restored with the path preserved, and the post-sign-in open redirect is now closed by a reject-by-default allowlist that is actually wired. Watch for: the change edits `src/pages/account/sign-in.tsx`, a file requirement 8 names as untouchable, on an owner clearance that is attested only inside the change itself (confirmed). The `[retired public path ef531503]` → home 302 **preserves the attacker-controlled query string**, which requirement 6 says is dropped, and no document in the change measures or mentions it (confirmed). Three of the surface categories requirement 4 names — OAuth callbacks, signed receipt links, verified-email callbacks — have no row and no statement in the matrix document, so "not deleted and still working" is unevidenced for them (confirmed).

## The forbidden-path edit, and the requirement it is trading against

Requirement 8 lists `src/pages/account/**` among the files that must not be modified. Commit `d0584e94` modifies `src/pages/account/sign-in.tsx`: one import, one line in `returnPathFromUrl()`, and the deletion of a comment claiming the old regex "can never be turned into an open redirect".

The edit is right on the merits. The regex it replaces is `/^\/[a-zA-Z0-9/_-]*\/?$/`, and both of the inputs the change names do pass it: `//evil`, where every character is in the class and a browser reads the leading `//` as protocol-relative with `evil` as the host, and `/workspace/access`, a well-formed local path that is the staff login. `src/lib/safeReturnPath.ts` is a sound reject-by-default allowlist — exactly one leading slash, a second `/` or `\` rejected before anything else, `[\\\s\u0000-\u001f\u007f%?#:]` rejected anywhere, `..` segments rejected, staff first segments rejected case-insensitively, no URL-decoding at any point, and the accepted value re-emitted from the allowlist rather than sliced out of the input so it cannot smuggle a query or fragment. It returns the value to use, not a boolean, mirroring `safeHttpHref`.

So requirements 6 and 8 pull in opposite directions here: leaving the file alone leaves a live open redirect and a validator with no caller, which is what the previous pass flagged. The change resolves that toward security and documents why — the owning `customer-session` workstream aborted before implementation (its task directory holds only baseline, design and design-review, no implementation), and `sign-in.tsx` was clean in `git status`, so there was no live owner to collide with. I confirmed both.

What is missing is the authority trail. The owner clearance appears in the commit message, in `src/lib/safeReturnPath.ts`'s header, and in §7.1 and §9.4 of the matrix document — all three inside the change being reviewed. `docs/execution/change-authority-matrix.md` carries entries for the home-fallback workstream's far larger production writes but nothing for this boundary crossing. A constraint waived only by the change that benefits from it is not evidenced, and this repo's own convention is that the matrix is where authority lives.

## The query string is not dropped

Requirement 6 opens with "untrusted path, query and fragment are dropped on a redirect home". Measured:

```
[retired public path ef531503]/?next=https://evil.example   302 -> https://wecare.digital/?next=https://evil.example
[retired public path ef531503]?a=b&c=d                      302 -> https://wecare.digital/?a=b&c=d
[retired public path ef531503]/x/y?return=//evil            302 -> https://wecare.digital/?return=//evil
```

The path is dropped. The query is appended to the canonical home, because that is what Amplify does with a redirect target. The plan's design note D1 asserted the opposite — "the target is a literal `/`, so no path, query or fragment is forwarded" — and that assertion travelled into the change without ever being probed. The matrix document mentions a query string exactly twice, both times about CloudFront cache keys.

The effect today is inert, and worth stating so the fix is not over-scoped: the `Location` host is a fixed literal, so this is not an open redirect, and neither `src/pages/index.tsx` nor `src/pages/_app.tsx` reads `location.search`, `URLSearchParams` or `router.query`. The two other paths home do drop everything — `src/pages/404.tsx` calls `router.replace` with a literal `'/'`, and the home-fallback viewer-request function discards path and query, which I confirmed at the edge (`shop.wecare.digital/some/path?q=1` → `https://wecare.digital/`, bare).

That asymmetry is the point. One of three routes home behaves differently from the written requirement, and the difference is undocumented.

- Razorpay verification and webhook routes — covered, and I re-measured `POST /api/razorpay-webhook` at 401 returning `{"error": "Invalid signature"}` rather than a page.
- Registered storefront pages — covered; 12 rows, plus I sampled sitemap entries and two `/shop/**` product pages at 200.
- Protected operational endpoints — thin. `POST /api/auth/validate` 401 is the only row. I measured `/api/invoices`, `/api/contacts` and `/api/wix-store/products` all at 401 with `{"error": "No authorization token provided"}`; none appears in the document.
- Cognito/Meta/Wix OAuth callbacks — no row, no statement. The answer is good and specific: `src/pages/_app.tsx` registers `redirectSignIn`/`redirectSignOut` as the apex `https://wecare.digital/`, which measures 200 and whose query string survives a `www` 301, so the `?code=` round trip is intact. - Signed receipt links and verified-email callbacks — no row, no statement. `/api/checkout/download-receipt` answers 404 and no receipt path is referenced from `src/`; the email-verification function is recorded elsewhere as built but deliberately not provisioned.

Every one of those is fine. The gap is that a reader cannot distinguish "preserved" from "never existed" from "not checked", and requirement 4 is explicitly about evidence. Three sentences and two rows close it.
