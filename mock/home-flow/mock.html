Fix 1 · worst offender

The copy column has no max-width, so line length doubles at ≤1024px

On desktop the column sits in a fixed 380px track — 47 characters per line, a proper measure. At 1024px and below the grid collapses to one column and the column inherits the full page width with no cap at all, so the same paragraph runs 120 characters. The convention is 45–75. Both neighbours on this same page already cap themselves — .home-sub at 560px, .home-close-lead at 782px — so this column is the outlier on its own page. Flaw 4 · reported, not fixed

The two columns end 136px apart on desktop

The panel is a hard height:650px; the copy measures 514px. So the band has a ragged bottom edge of 136px at 1280, 1440 and 1920. align-items:start is deliberate and correct — centring the copy against a 650px panel would leave a gap above and below — so this is the cost of a fixed-height panel beside fluid prose, not a bug. Closing it would mean padding the copy with something it does not need, or shortening the transcript. Stated rather than fixed.
