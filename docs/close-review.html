C1 — The button's edge against its own panel is 1.18:1

#d1f470 fill + #d1f470 border on rgba(209,244,112,.22)

WCAG 1.4.11 asks for 3:1 between a control's boundary and what is adjacent to it. This button is solid lime with a 2px lime border, sitting on a 22% lime panel — so the border contributes nothing and the whole control measures 1.18:1. It is the page's only action, and its shape is carried almost entirely by the text inside it.

index.tsx states the opposite outright: "Solid lime on the tinted panel still separates because the panel is the same hue at 22% — the button is the saturated version of its own background, which is why it needs no shadow at rest." That reasoning is why the defect is there — being the same hue is exactly what removes the contrast. Composited, the two colours differ by 1.18:1.

The change: border-color: #d1f470 → #1a3a2a. The fill stays lime, so it is still the site's lime affordance; it gains an edge. 1.18:1 → 11.85:1. No new colour — #1a3a2a is already the text inside this button and the eyebrow above it.

after — 11.85:1
MED

C2 — The focus ring on that same button is 1.51:1

outline:3px solid rgba(26,58,42,.22)

Same criterion, same panel. A 22% alpha of the dark green over a pale lime tint composites to 1.51:1. This is the only focusable element in <main> on the entire page, so a keyboard visitor tabbing through the document gets one stop and almost no indication they have arrived at it.

The change: drop the alpha — rgba(26,58,42,.22) → #1a3a2a. 1.51:1 → 11.85:1. outline-offset:3px stays, and it is what keeps the ring legible as a ring now that the border is the same colour: 3px of panel tint separates them.

after — 11.85:1
how a frame can show a focus ring at all

It cannot, natively — :focus-visible needs a keyboard and a preview frame has none, the same way prefers-reduced-motion cannot be set inside one. So the declared outline is applied through a class instead: the before frame gets rgba(26,58,42,.22) exactly as the stylesheet declares it, the after frame gets the fix. Read from the stylesheet rather than the element, because getComputedStyle on an unfocused link returns the resting outline — currentColor at full opacity — which is how the first version of the probe measured 11.85:1 and passed a ring that does not exist.

C3 — On hover the button loses its outline entirely

.home-close-cta:hover{background:#fff}

Hover swaps the fill to white while the border stays lime, so the control's edge against the pale panel measures 1.18:1 — a white shape with a near-invisible outline floating on lime tint. The translateY(-2px) and the soft shadow are doing all the work of saying it is a button.

No separate change needed — the C1 border fix repairs this too, which is the main reason to prefer it over darkening the fill.
