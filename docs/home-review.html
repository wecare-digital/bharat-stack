CHANGES

Three repairs — one line each

A  The word is missing entirely without JavaScript, and for ~200ms on every single load.

why / the code

cycleW starts null, so the first render writes no inline width. .home-cycle is overflow:hidden and all four words are position:absolute, so they add nothing to its intrinsic width — it computes to 0px and clips the word away. Measured on a normal load, JS working, local server, no network: 4 painted frames, ~200ms.

.home-cycle{width:max-content}   /* resting width, needs no JS */
.home-cyc-word.on{
  position:static;      /* the visible word sits in flow, so the pill has a width */
  display:inline-block; /* NOT optional - see below */
}

display:inline-block is load-bearing, and measuring this mock is what caught it. position:static alone makes the span a non-replaced inline box, whose offsetWidth is 0 — so the existing effect would write width:0px over max-content and the pill would collapse on every load with JavaScript, turning a 200ms flash into a permanent one.

B  Resize with reduced motion on and the word stays cut — 96 px, 35% of it — for good.

why / the code

Width is measured in an effect keyed on the word index alone; there is no resize listener. The font is clamp(36px,4.3vw,60px), so width is a function of viewport width. On a normal load a stale value self-heals at the next 2400ms tick; under reduced motion the interval never starts, so it is final. Reproduced here by writing the 182 px width measured at 390 onto a 1280 frame, where the word needs 278 px.

const ro = new ResizeObserver( measure );   // not window.resize: this also
if ( markRef.current ) ro.observe( markRef.current );  // catches a webfont swap
return () => ro.disconnect();

C  Reduced motion can park a white shutter over the tint — latent today, one edit away from live.

why / the code

The reduced-motion block sets the shutter to scaleX(1) — the start state — under a comment saying it settles the pill into its resting state, which is scaleX(0). The dot's sibling rule is correct, so it is a slip. It is overridden today only because .home-layout.show .home-mark::before scores (0,2,1) against this rule's (0,1,1).

@media(prefers-reduced-motion:reduce){
  .home-mark::before{transform:scaleX(0)}   /* was scaleX(1) */
}
PROOF

Nothing visible changed

Normal load, side by side. Measured: pill 280px both, h1 131 px both at 1280 and 90 px both at 390 — so the reflow pin and the 2400ms page-jump guard still hold.

REST

Housekeeping, and two calls for you

No visual change, same commit: permanent will-change:width; a max-width:900px on the h1 that never binds; the h1's raw text repeating the word set five times; nine stale comments.

Your call, not mocked: the 9.6s rotation that cannot be paused, and 80 px of blank above the first word.

detail
  • will-change:width should be set shortly before a transition and released after; left on it holds compositing resources for the page's life, and under reduced motion there is no transition to hint at. Not applied in the panels — a performance judgement.
  • max-width:900px never binds: .home-hero is align-items:flex-start, so the h1 shrink-wraps to 506 px at 1280.
  • The h1's raw text — screen readers are correct, but a naive extractor reads:
    Everyday AI, built forconsumers, enterprises, climate tech, frontier techconsumersenterprisesclimate techfrontier tech
  • Comments contradict the band in nine places, two measurable: the header says climate tech is 290px with an 83px spread across five words; animcheck measures 298px and 22px across four.
  • Rotation: WCAG 2.2.2 covers content moving automatically past five seconds. Hover+focus pausing adds no furniture; a strict reading wants a user-operable control, which is furniture in a band meant to carry none.
  • The 80 px was tuned around the deleted lime brand badge. Purely cosmetic.
