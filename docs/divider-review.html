The argument against
Needs JavaScript to arm, like the footer dash and the hero pill — so it is written the same way: the CSS ships the FINISHED state and JS adds .is-armed only once it knows it can animate. No JS means three visible lime bars, exactly as today.

My recommendation: D. Keep one lime, add the staggered draw.

The reason is not taste. The five-colour tint/dot set in this repo is documented as “a per-subject system that sits outside the brand palette by design”, and it is used where each item names a different subject — the rotating words in three separate heroes. These three beats are the opposite case by the source’s own account: one idea stated three ways, which is why the fourth beat was removed rather than recoloured.

What you are reacting to is real, though, and it is my doing. Equalising the bars to 118px in #77 removed the last thing that differed between them — they are now identical in colour, thickness and height. Motion restores the difference without making a claim: it says order, which the list actually has, instead of category, which it does not.

If you want colour anyway, take B over C. Colour and motion both saying “these are separate” is the same point twice, and the stagger is the weaker of the two.

Why 14
A little over half this line’s 24px line box, so the movement registers without reading as a jump. 560ms keeps its velocity near the dash’s rather than making the line faster for being farther. footerprobe.js now asserts travel ≥ 12px, because the frame counts were already green at 6px and could not be the guard.
