3 · How translation actually works

  1. Visitor types a language and picks it. The choice is saved to localStorage, so it persists across pages and visits.
  2. The widget walks the page's text and collects every readable text node. It skips code, inputs, SVG, and anything marked data-wc-no-translate — which is how dashboard customer data is protected.
  3. Text is sent in batches (max 30 items / 20KB each) to api.wecare.digital/site-language/translate.
  4. The Lambda translates and caches the result in DynamoDB. The API key stays server-side in Secrets Manager — a browser widget can never hold one. If Google fails it falls back to Amazon Translate automatically.
  5. Each translated string is written back in place. The originals are kept in memory, so switching back to English restores the exact text — nothing is re-fetched and nothing is lost.
  6. Listen sends the page text to /tts, which returns audio from Amazon Polly and plays it. Only offered for languages that actually have a voice.

If the translation service is unavailable, the translate button simply hides — the WhatsApp button still works. That was a real bug before: the old component returned nothing at all when the language list failed, which would have taken customer support down with it.
