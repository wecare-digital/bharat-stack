# robots.txt for wecare.digital
#
# WHY THIS FILE CARRIES SO MANY Disallow LINES.
# next.config.js sets output:'export', so the authenticated dashboard is exported as
# static HTML into the SAME bucket as the public marketing pages. Every dashboard route
# is therefore fetchable by a crawler that guesses the path. Those pages render an empty
# shell for an unauthenticated visitor, so indexing them adds nothing and publishes the
# internal route map. Authentication gates the DATA, not the HTML; this file is what
# keeps the routes out of the index.
#
# THE RULE: a top-level segment in the export belongs in exactly one of two places —
# the sitemap allowlist (PUBLIC_EXACT in scripts/generate-sitemap.js) or a Disallow
# below. Audited 2026-09-25 against the built export, which found five authenticated
# segments in neither: /commerce/, /docs/, /growth/, /nocode/ and /service/.
#
# /growth/ and /nocode/ were then DELETED outright later the same day, along with
# /carbon/, /forms/create/ and /link/create/, so their rules came back out again — a
# Disallow for a route that no longer exists is noise that implies the route does. The
# three that remain are real: /commerce/, /docs/, /service/.
# Re-run that audit after adding any top-level route.
#
# Deliberately NOT disallowed: /images/ holds public assets referenced by the marketing
# pages, and blocking it would stop those images being indexed.

User-agent: *
Allow: /

Disallow: /api/
# /mock-home/ arrived in ef1abc5b, a design mock of the home page. Added within minutes of
# the audit below reaching zero gaps, which is the whole argument for re-running it rather
# than trusting the number: a mock of the home page is the worst possible thing to leave
# indexable, because it competes with the real home page for the same query.
Disallow: /mock-home/
# /store/ is NOT one of the families that moved under /workspace/. It is still a live
# top-level route (1 page, 1 built route) and absent from the sitemap, so it keeps its
# own rule. It was removed by mistake during the nesting change and restored in the
# same commit — the audit rule at the top of this file is what caught it. /carbon/ by
# contrast is an empty directory building zero routes, so it correctly has none.
Disallow: /store/
# All fourteen authenticated families nested under /workspace/ on 2026-09-26, so their
# individual Disallow lines came out rather than being kept alongside: a Disallow for a
# route that no longer exists is noise that implies the route does. That covers
# access, admin, commerce, contacts, dashboard, docs, engage, forms, link, pay, seo,
# service, settings and task.
#
# /engage/ was itself the former /dm/, by way of /workspace/ for about twenty minutes,
# and is now /workspace/engage/. Every old prefix 301s in the Amplify custom rules and a
# crawler following any of them lands here on this Disallow, which is the intended
# outcome. /api/ stays separate because it is a live root path, not a moved one.
Disallow: /workspace/

# ── AI crawlers and answer engines ────────────────────────────────────────────────
#
# THE TRAP THIS BLOCK EXISTS TO AVOID, stated first because it is counter-intuitive.
# A named User-agent group REPLACES the `User-agent: *` group for that agent - robots.txt
# has no inheritance. So the obvious way to welcome an AI crawler:
#
#     User-agent: GPTBot
#     Allow: /
#
# does not mean "same as everyone else, and welcome". It means GPTBot gets a group with no
# Disallow at all, which GRANTS it /workspace/, /api/ and /store/ - the authenticated
# dashboard that the * group above is the only thing holding out of the index. Welcoming a
# crawler by name and handing it the internal route map is the same edit.
#
# Hence the four Disallow lines are repeated verbatim below. If a line is added to the *
# group above, it must be added here too. scripts/generate-llms-txt.js and
# scripts/generate-sitemap.js both fail the build when an advertised URL is Disallowed, so a
# contradiction in ONE direction is caught automatically; this direction - a named agent
# being granted more than * - is not, and is why the duplication is deliberate rather than
# sloppy.
#
# WHY NAME THEM AT ALL, given * already allows them. Two reasons. Google-Extended is not a
# crawler but a control token for Gemini and Vertex grounding, so its absence and its
# presence-with-Allow are different statements and only the second is a decision on the
# record. And naming the set is what makes a future opt-out a one-line change to a group
# that already exists, rather than a new group somebody writes in a hurry and gets wrong in
# the way described above.
#
# Not named, deliberately: CCBot (Common Crawl feeds training corpora we have no
# relationship with) and the SEO backlink crawlers. Their absence leaves them under *,
# which allows them - this is a list of agents we have thought about, not a whitelist.
